## 0. 项目定位（先读这个）

- **首要目的**：展示**产品意识 + 和 AI 协作（vibe coding）的能力**；不追求功能做多全。
- **核心理念**：看病理以临床为导向。checklist 的作用是**规范阅片工作流**、引导阅片人做出正确判断；随着熟练度提高，checklist 逐步缩短（脚手架渐退）。
- **内容可信度原则**
  1. **AI 不撰写任何判定依据**：不生成针对单张切片的讲解文字
  2. 所有提示文字都要**摘录或转述自权威来源，并附链接**（PathologyOutlines、WHO 分类、教科书、Pathweb 等）；Devin 只做编辑，没有出处的条目就不写
  3. AI 只输出**区域轮廓**（检测模型的结果），醒目标注「AI 生成，非专家标注」，**不计分**

## 1. 一句话 / One-liner

- **中文**：给病理新人的肺癌阅片教练。先看部位、再按工作流一步步看片，自己判断是不是癌、是腺癌还是鳞癌；提交后对照官方标签和 AI 区域参考，用错题本跟踪自己的进步。
- **EN**: A clinically-oriented slide-reading coach for pathology beginners — start from the site, follow a structured workflow, call benign / adenocarcinoma / squamous, then compare with ground-truth labels and AI region references, and track progress via a mistake log.

## 2. 用户与目标

- **用户**：病理新人（第一个，也是 MVP 阶段唯一的用户就是 Chu 本人），后期找 1–2 个非医学背景的同学做观察式试用
- **任务**：已知部位和临床信息 → 判断**是否为癌 + 大类（正常 / 腺癌 / 鳞癌）** → 在切片上找出证据
- **目标**
  - G1：按规范的工作流独立读完一张切片
  - G2：在**没见过的切片**上，腺 / 鳞 / 正常的鉴别正确率有可测量的提升
  - G3：随着熟练度提高，checklist 逐步缩短
- **非目标**：不做诊断、不做 AI 自动判读、不让 AI 写判定依据、不做账号和后端

## 3. 阅片工作流（checklist 骨架）

| 步骤                   | 内容                                                                         | 说明                                                   |
| ---------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------ |
| **0 部位卡片（强制）** | 切片解锁前，先**主动回忆**：该部位的正常组织由什么构成？常见的癌有哪些类型？ | 新手档给选项和提示，专家档必须自己写；不填写不解锁切片 |
| 1 组织类型             | 识别组织成分，确认和申请单上的部位相符                                       |                                                        |
| 2 染色类型             | 确认染色（MVP 只有 H&E），检查制片质量                                       |                                                        |
| 3 预判                 | 结合临床信息（部位、年龄、性别、吸烟史）做初步判断                           | 只用 TCGA 真实字段，不编主诉                           |
| 4 特征 1–5             | 低倍 → 中倍 → 高倍，逐项判断：有 / 无 / 不确定；每项可以标注证据位置         | 每项提示都附来源链接                                   |
| 5 结论                 | 正常 / 腺癌 / 鳞癌 + 关联的证据标注                                          | 提交后才揭晓答案                                       |

**熟练度三档**（Q2）

| 档位 | checklist 形态                         |
| ---- | -------------------------------------- |
| 新手 | 完整检查项 + 来源提示 + 特征图谱示例图 |
| 熟练 | 只有检查项，没有提示                   |
| 专家 | 只剩步骤标题；第 0 步必须自己写        |

- 用户手动切换；系统在**最近 6 张判对 5 张**时建议升一档，不强制

## 4. 功能规格（P0）

**F1 病例库**：卡片显示部位、染色、档位推荐；卡片上**不显示**诊断标签。验收：练习病例 16 张都能打开。

**F2 切片浏览器**：OpenSeadragon，支持缩放、平移、小地图、比例尺；显示等效倍数（2× / 4× / 10× / 20× / 40×），并提供快捷按钮。验收：桌面版 Chrome / Edge 流畅浏览；中国大陆网络下首屏 5 秒内显示（尽力而为）。

**F3 引导式阅片**：按第 3 节的工作流推进；三档切换；第 0 步不完成就不解锁切片；模板用 JSON 定义（以后扩展器官只改 JSON）。

**F4 证据标注**：打点、矩形、多边形；每个标注关联一个 checklist 项，可以附备注；点击标注列表跳转到对应位置；刷新后标注不丢。

**F5 揭晓与对照**（v1.0 的 F7 并入）

- 提交结论**之前**，标签和 AI 轮廓都不可见
- 提交后显示：TCGA 官方诊断（对 / 错）+ AI 检测轮廓图层（可开关，标「AI 生成，非专家标注」）
- 用户逐个对照 AI 轮廓自评：「我找到了 / 我漏了 / 我觉得 AI 标错了」（自评数据也作为用户研究素材）

**F6 特征图谱**：每个 checklist 特征配 2–3 张**专家标注过的 CC BY 图块**（来自 LC25000、NSCLC-TME 等），并附来源链接和数据集引用。

**F7 报告导出**：病例信息、工作流结果、证据截图和备注、结论、揭晓结果、免责声明；格式为 Markdown 和 PDF（浏览器打印），语言跟随界面语言。

**F8 学习记录 / 错题本**

- 混淆矩阵（你的判断 vs TCGA 标签）
- 错题列表：点开直接回到那张切片，并显示你当时的标注
- 正确率曲线 + 升档建议
- **留出测试模式**：练前测 6 张 / 练后测另外 6 张，测试时没有任何提示，结果单独统计

**F9 本地存储与双语**：数据存在 localStorage / IndexedDB，没有账号和后端；支持导出 / 导入 JSON 存档；中英一键切换，默认英文；来源摘录保留原文语言，另附中文转述。

### Backlog（MVP 之后）

- 扩展器官：食管、宫颈（同一器官内的腺 / 鳞鉴别），只需加 case.json
- 小细胞癌（TCGA 没有，需要另找数据源）
- 本地私有模式（私有 .tif 本机切瓦片，数据不出本机）
- QuPath 结果叠加（细胞计数、Ki67 阳性率等 IHC 定量）
- 自测模式（随机图块快速判断）、双切片同步浏览、类器官模板

### 明确不做

诊断结论、AI 撰写的判定依据、账号和权限、后端数据库、移动端适配、运行时调用大模型。

## 5. 数据

| 用途          | 数量                          | 来源                                                                 |
| ------------- | ----------------------------- | -------------------------------------------------------------------- |
| 肺·练习       | 正常 4 + 腺癌 4 + 鳞癌 4 = 12 | TCGA-LUAD / TCGA-LUSC（正常切片取配对的 Solid Tissue Normal）        |
| 其他部位·练习 | 腺癌 2 + 鳞癌 2 = 4           | TCGA 其他项目（如结直肠或胃的腺癌、食管或头颈的鳞癌），由 Devin 挑选 |
| 留出测试      | 6 + 6 = 12                    | TCGA 肺，不进病例库                                                  |
| 特征图谱      | 每个特征 2–3 张               | LC25000、NSCLC-TME（Zenodo，CC BY 4.0），使用前需核实 license        |
| 区域参考      | 每张练习切片                  | 离线运行检测模型生成轮廓（见第 6 节）                                |

- 临床字段：部位、年龄、性别、吸烟史，都取自 GDC 的 clinical 数据
- 引用：页脚和 README 写明 TCGA Research Network 致谢语，以及各数据集的引用
- 已核实：IDC 上的 TCGA 肺切片**没有专家标注的区域**，只有 AI 生成的细胞核分割和淋巴细胞浸润图。ACDC-LungHP 有专家癌区标注，但需要注册、license 不明、不分型；**不放进程序**，由 Chu 自己去官网练习

## 6. 离线 AI 轮廓流水线

1. GDC 下载 SVS → pyvips 切 DZI 瓦片 → 上传 R2
2. WSInfer 运行 `lung-tumor-resnet34.tcga-luad`（HF: kaczmarj）→ 得到肿瘤概率热图 → 阈值化，转成 GeoJSON 轮廓
   - 风险：该模型是在 **LUAD** 上训练的，对 LUSC 的效果未知。开发时先拿 2 张 LUSC 实测；效果差就换 `pancancer-tissue-classifier.tcga` 之类的模型，或者对鳞癌病例不显示轮廓。模型 license 待核实。
3. 输出静态 `regions.geojson`，与 case.json 一起上线；Chu 抽检后可以加「已人工核对」标记
4. **不使用视觉大模型，不生成任何文字**

## 7. 数据结构

```
case.json     { id, site, clinical: {age, sex, smoking}, stain, split: "practice|pretest|posttest",
                truth: "normal|adeno|squamous", source, dzi, mpp, templateId, regions: "regions.geojson" }
template.json { id, steps: [ { id, targetMag, title{zh,en}, levels: ["novice","proficient","expert"],
                items: [ { id, label{zh,en}, hint{zh,en}, sources:[{title,url}], atlas:[imgId] } ] } ] }
session       { caseId, level, step0Answers, answers{itemId:{value,note}}, annotations[],
                conclusion, revealedAt, selfReview{regionId:"found|missed|aiWrong"}, updatedAt }
```

## 8. 技术架构（沿用 v1.0）

Vite + TypeScript + OpenSeadragon（加标注层）纯静态 SPA；托管在 Cloudflare Workers Static Assets 或 Pages；瓦片放 R2（Pages 有 2 万文件的限制）；数据处理用 Python（pyvips、WSInfer）；开源到 GitHub（MIT）。

## 11. 风险与对策

| 风险                          | 对策                                     |
| ----------------------------- | ---------------------------------------- |
| 检测模型在鳞癌上效果差        | 先实测；换模型，或者对鳞癌不显示轮廓     |
| 提示内容不准确                | 全部可溯源；没有出处的不写               |
| n=1 说服力弱                  | 留出测试集 + 观察式试用；对外如实写 n=1  |
| 国内访问 Cloudflare 慢        | 512 px 瓦片 + 缓存；必要时绑定自定义域名 |
| 图块数据集 license 不允许展示 | 使用前逐个核实，不允许的就换             |
