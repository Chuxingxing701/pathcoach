# PathCoach 开发计划 v1（基于 MVP v2.0）

> 状态：**已通过**（Chu 2026-11-03：「没有新改动」）· 分工：Chu = 产品 / 审核 / 唯一用户，Devin = 全部代码与数据处理
> 节奏：Chu 每天 1.5–2 小时；约 4 周；停工审核点 R0–R4 + 发布审查 R5

---

## 1. 审核机制（所有审核点通用）

- **触发**：Chu 说「停工 R{n}」或 Devin 到达节点自动停工，等审核结果再继续。
- **Devin 交付「审核包」** `docs/reviews/R{n}.md`，固定结构：
  1. 本阶段目标 vs 实际完成（对照 v2.0 验收项，逐条 ✅/❌）
  2. 设计取舍与理由（含放弃的方案）
  3. 已知问题 / 技术债
  4. 需要人拍板的事项
  5. 验证证据：公开网址、测试结果、截图 / 录屏
  6. 下一阶段计划
- **审核产出**：高级模型按 **Blocker / Major / Minor** 分级给意见；**Blocker 清零才解锁下一阶段**，Major 必须排期，Minor 记入 backlog。
- **审核视角**（给高级模型的提示词骨架）：① 是否偏离「展示产品意识 + AI 协作」的首要目的；② 内容可信度三原则有没有被破坏；③ 不可逆节点（练前测、公开发布）前的风险；④ 范围蔓延。
- **开发规则**：一个功能一个 PR，PR 描述写对应的 F 编号和验收项；所有决策写进 `docs/decisions.md`（ADR 形式），审核包直接引用；Chu 不审代码，只审产品、内容和证据。

## 2. 阶段与步骤

### M0 · 项目初始化（第 1–2 天）

**Devin**

1. 建仓库、Vite + TypeScript 骨架、ESLint / Prettier / typecheck、GitHub Actions（lint + build）
2. 定义数据结构的 TypeScript 类型 + JSON Schema：`case.json` / `template.json` / `session`（v2.0 第 7 节），写校验脚本
3. Cloudflare 部署流水线跑通：一个占位页上线到公开网址；R2 bucket 建好，做 1 张切片的端到端试验（SVS → DZI → R2 → OpenSeadragon 能打开）
4. `docs/decisions.md` 初始化（记录：静态站无后端、瓦片走 R2、truth 在前端 JSON 中仅做 UI 盲态而非防作弊 等取舍）
   **Chu**：提供 GitHub / Cloudflare 授权；确认仓库名和域名
   **产出**：公开网址（占位页）、1 张切片可浏览、schema

> ### 审核点 R0 · 架构与数据模型
>
> 审什么：仓库结构、三个 schema 是否够用且不过度设计、R2 + 静态站的部署方式、国内访问实测速度、ADR 是否完整。
> 为什么停：schema 一旦有 16 + 12 张病例数据和模板内容之后再改，重做成本最高。

### M1 · 数据管线（第 3–6 天）

> 执行细化（Chu 2026-11-13 确认）：制片按 ADR-006（肺部全冰冻、其他部位 FFPE），瓦片按 ADR-003（1024 px / 静态 Worker，不用 R2）。

**Devin**

1. **GDC 选片 28 张**（ID 一律无含义编号 `lung-01…24` / `other-01…04`）：

   | 分组 | 数量 | 类别 | 制片 |
   | --- | --- | --- | --- |
   | 练习 | 12 | 肺正常 4 + 腺 4 + 鳞 4 | 全冰冻 |
   | 练前测 | 6 | 正常 2 + 腺 2 + 鳞 2 | 全冰冻 |
   | 练后测 | 6 | 正常 2 + 腺 2 + 鳞 2 | 全冰冻 |
   | 其他部位练习 | 4 | 腺 2 + 鳞 2 | FFPE |

   - 练前 / 练后两组按大小、倍数、类别配对，难度可比
   - 其他部位候选：腺 → 结肠 COAD / 胃 STAD；鳞 → 宫颈 CESC / 头颈 HNSC / 食管 ESCA（乳腺按 ADR-005 排除）
   - 筛选：open access、SVS ≤ 150 MB、有 mpp、clinical 含年龄 / 性别 / 吸烟史
   - 给 Chu 一份不含诊断的清单（id、部位、split、制片方式）
2. 下载 → pyvips 切 DZI（1024 px JPEG Q80、无重叠、跳过空白、封顶 20×）→ 部署瓦片 Worker（预计 2 个，`v1/` 版本目录）
3. 生成 `cases/*.json`（无标签无出处）+ `answers/*.json`（truth + 诊断 + GDC 出处）+ `manifest.json`；clinical 只抄 GDC；`validate:data` 含泄漏检查必须全过
4. 切片质量抽查（Devin）：大面积空白 / 折叠 / 笔迹 / 染色异常 → 换片，更换记录进审核包
5. 写 `data/README.md`：来源、引用、致谢语、脚本复现步骤
6. 并行启动 WSInfer：先对 2 张 LUSC 实测 `lung-tumor-resnet34.tcga-luad`，出一页效果对比 + 核实模型 license（给 R3 决策用，不阻塞 M1）
7. 部署口径：瓦片和数据上 CDN，但主站 UI 不开放练习库；M2 只上线 `/test` 入口
   **Chu**：**不要看任何切片**；只看不含诊断的切片清单
   **上报规则**（不等 R1）：候选不足需放宽筛选 / 换部位、WSInfer license 或效果问题、其他偏离 ADR / 规格的决定
   **产出**：28 张切片在线可浏览、manifest、数据 README、LUSC 实测报告

> ### 审核点 R1 · 数据与许可
>
> 审什么：TCGA 使用条款与致谢是否合规；clinical 字段是否全部来自 GDC（没有编造）；pretest / posttest / practice 隔离是否可靠（Chu 在练前测前有没有可能看到练习集）；每类样本是否足够典型；瓦片清晰度 / 加载速度。
> 可与 R2 合并（如果 M1、M2 同一周完成）。

### M2 · 切片浏览器 + 练前测页面 + 上线（第 7–9 天）

**Devin**

1. F2 切片浏览器：OpenSeadragon、缩放 / 平移 / 小地图 / 比例尺、等效倍数显示 + 2× / 4× / 10× / 20× / 40× 快捷键
2. F9 骨架：localStorage / IndexedDB 封装、JSON 导出 / 导入、i18n 框架（默认英文）
3. **留出测试模式（F8 子集）**：独立入口 `/test`，6 张 pretest，无任何提示、无 checklist、无 AI 轮廓；只给临床信息 + 切片，选 正常 / 腺 / 鳞 + 自信度，记录每张用时；做完才显示成绩并锁定不可重做；结果可导出 JSON
4. 部署到公开网址；桌面 Chrome / Edge 实测；中国大陆网络首屏时间记录
   **Chu**：审核通过后做**练前测**（一次性，约 40–60 分钟），导出结果 JSON 存档
   **产出**：公开网址上的练前测页面、浏览器组件

> ### 审核点 R2 · 练前测冻结审查（不可逆节点）
>
> 审什么：测试流程是否完全无提示、无标签泄漏（含 URL、devtools 以外的正常可见面）；计分、用时、导出是否正确；6 张 pretest 与 6 张 posttest 难度是否可比（类别均衡、放大倍数可比）；浏览器加载是否流畅到不影响测试。
> 为什么停：练前测只能做一次，做错了练前 / 练后对比就作废。**R2 通过 → Chu 做练前测 → 才允许 Chu 接触 M3 的练习病例库。**

### M3 · 核心阅片闭环（第 10–16 天）

**Devin**

1. F3 引导式阅片：`template.json`（肺模板 v1：步骤 0–5，特征 1–5 每项带 `sources[]`），三档渲染，第 0 步不填不解锁切片，升档建议（近 6 张对 5 张）
2. F1 病例库：卡片（部位 / 染色 / 推荐档位），不显示标签；16 张练习病例
3. F4 证据标注：点 / 矩形 / 多边形，绑定 checklist 项，备注，列表跳转，持久化
4. F5 揭晓对照：提交前隐藏 truth 与轮廓；提交后显示 TCGA 诊断 + AI 轮廓图层（可开关，标「AI 生成，非专家标注」）+ 逐轮廓自评（找到 / 漏了 / AI 标错）
5. AI 轮廓流水线定稿：根据 M1 的 LUSC 实测决定 → 继续用 LUAD 模型 / 换 pancancer 模型 / 鳞癌不显示轮廓；输出 16 份 `regions.geojson`；核实模型 license
6. **checklist 内容编辑**：每条提示摘录或转述自 PathologyOutlines / WHO / Pathweb 等并附链接；中英双语；无出处的不写。产出一份「来源对照表」给 Chu 审
   **Chu**：审来源对照表（每条提示点开链接核对一遍）；抽检 AI 轮廓 3–4 张
   **产出**：完整的「看部位 → 工作流 → 判读 → 提交 → 揭晓 → 自评」闭环上线

> ### 审核点 R3 · 核心闭环与内容可信度（最重要的一次审核）
>
> 审什么：
>
> - 内容可信度三原则：无 AI 撰写的判定依据；提示 100% 有出处；轮廓标注醒目且不计分
> - 盲态是否严格：提交前任何正常界面不出现 truth / 轮廓
> - 工作流是否真的「临床导向」且三档缩短合理；第 0 步强制是否会让用户烦（可用性）
> - 模板 JSON 是否真的能靠加文件扩展到食管 / 宫颈
> - AI 轮廓方案决策是否有实测证据支撑
>   通过后 Chu 开始每天练 2–3 张（练习数据同时成为 M4 的测试数据）。
